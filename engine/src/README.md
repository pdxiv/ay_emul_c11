# engine/src/

Top-level engine sources; this directory currently holds only the format-agnostic player dispatcher. Individual chiptune/tracker format loaders and hardware emulation live in the `formats/`, `hw/`, and `util/` subdirectories.

## player.c

Implements `player_load`/`player_load_song`, a unified front-end over all 18 formats `engine/` can load: it detects a file's format from a fixed-priority chain of content signatures (`ZXAY`+`EMUL` for AY, `YM2!`/`YM3!`/`YM3b`/`YM5!LeOnArD!`/`YM6!LeOnArD!`/LHA-wrapped `-lh5-` for YM, ProTracker-3/Vortex-Tracker title strings for PT3, `ICE!`/`SNDH` for SNDH, and a 2-letter id + mode byte for VTX), then falls back to a file-extension table (`.pt1`, `.gtr`, `.fls`, `.stc`, `.stp`, `.pt2`, `.fxm`, `.psm`, `.asc`, `.as0`, `.ftc`, `.psc`, `.sqt`) for formats with no byte signature, dispatching to that format's own `X_file_load`. It then provides format-generic accessors over the resulting tagged union (`player.as`): buffer rendering (`player_make_buffer`), end-of-song/loop control (`player_real_end_all`, `player_set_do_loop`), metadata (`player_get_metadata_raw`), the shared `ay_engine` handle for live mixer/filter tweaks (`player_ay_engine`, `player_set_chip_freq`, `player_set_player_freq`, `player_set_number_of_channels`), and seek-position bookkeeping (`player_get_tick_position`, `player_get_seconds_per_tick`).

The PT3 detector deliberately does not validate the byte-position title string it matches on; real Pascal's `FoundPT3` (Players.pas:5880-5967) never checks that text either, instead validating structural pointer/table offsets from byte 202 onward, so a PT3 file with a corrupted title still loads via the extension fallback exactly as it would in the original. `player_get_tick_position`/`player_real_end_all`/`player_set_do_loop` currently return real per-format data for AY/YM/VTX/SNDH/PT3 (PT3's duration comes from a ported `GetTimePT3`-equivalent, `pt3_get_time`) and for the 12 tracker formats covered by the `CheckLoopAndStop` port (their own `real_end_all`/`do_loop` fields); `player_get_tick_position`'s own header comment for the still-open MIG-0101 debt items (originally noting these were unwired) has since been resolved by MIG-0103/MIG-0104/MIG-0108, though MIG-0101 itself remains open (`behaviorally_incomplete`) as the umbrella tracking item for the full audit.

Ported from: ay_emul/Players.pas (`Module_Detector`/`FoundPT3` for format detection, `AddTrackerModule` for metadata field layout, `RerollMusic`/`Set_Chip_Frq`/`Set_Player_Frq`/`Set_Stereo` for the live playback-parameter and seek-position helpers).
