# engine/include/ay_engine/

Top-level public headers for the ay_engine static library. This directory currently holds a single header: the unified player dispatcher that sits above all the individual per-format loaders in `formats/` and the hardware core in `hw/`.

## player.h

Declares the `player` struct (a tagged union over all 18 supported `X_file` structs) and the `player_format`/`player_status` enums, plus the dispatch functions that detect a file's format from content signature or extension and route to the matching `X_file_load`/`X_file_make_buffer`/etc. Also declares GUI-facing helpers added at the Phase 5 GUI kickoff: multi-song selection (`player_load_song`, `player_song_count`), chip-type/frequency queries and live overrides (`player_chip_type`, `player_set_chip_freq`, `player_get_ay_freq`, `player_set_player_freq`), raw (CP1251, untranscoded) metadata extraction (`player_get_metadata_raw`), tick-position/seek support (`player_get_tick_position`, `player_get_seconds_per_tick` — real values for all 18 formats, see MIG-0101/MIG-0111), channel-count and loop control (`player_set_number_of_channels`, `player_set_do_loop`), and end-of-song/buffer generation (`player_real_end_all`, `player_make_buffer`). This header is new glue code with no single direct Pascal source file: its detection logic re-derives format signatures from `Players.pas`'s `Module_Detector`/`FoundFTC`/`FoundPSC`/`FoundSQT` heuristics and its `TAYFileHeader` constants (as cross-checked in the header's own file comment), while the GUI-facing accessors mirror pieces of `MainWin.pas` (`Set_Chip_Frq`, `Set_Player_Frq`, `Set_Stereo`) and `Players.pas`'s shared `PlConsts[0]` tick-counter convention, generalized across all 18 formats instead of being tied to one.

`player.h` also declares MIG-0112's playlist-level Turbosound pairing API: `player_supports_pairing`/`player_step_registers` (an explicit-`ay_chip*`-target generalization of `Players.pas`'s `All_GetRegisters[CNum](CNum)` dispatch, since this port has no single shared `SoundChip[0..1]` array), and `player_pair`/`player_pair_load_song`/`player_pair_make_buffer`/`player_pair_real_end_all`/`player_pair_set_do_loop`/`player_pair_free` — two independently-loaded `player`s sharing one `ay_engine` (the primary's own `chip`/`chip2`), mirroring `MakeBufferTracker` (Players.pas:12301-12317).

Ported from: no single ay_emul/*.pas file (new dispatch/adapter code); individual pieces trace to ay_emul/Players.pas (Module_Detector, PlConsts[0].Global_Tick_Counter/Global_Tick_Max, AddTrackerModule, TrModLoaded's `PlayListItems[Index]^.Next` pairing branch, MakeBufferTracker) and ay_emul/MainWin.pas (Set_Chip_Frq, Set_Player_Frq, Set_Stereo). MIG-0101 and MIG-0111 are both closed/validated: real tick-position/duration values are wired and oracle-confirmed for all 18 formats, not just AY/YM/VTX/SNDH/PT3 — an earlier version of this note said otherwise but had gone stale. Open migration debt: MIG-0112 (behaviorally_incomplete) — the playlist-pairing mechanism itself is implemented and unit-tested (see tests/engine_smoke/test_player_pair.c), but has no real Pascal-oracle validation of the end-to-end `.ayl`-driven path yet.
